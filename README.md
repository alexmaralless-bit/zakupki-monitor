# Монитор госзакупок

Лидогенератор по тендерам с zakupki.gov.ru для одного пользователя, устанавливается на своём компьютере. Один раз настраиваете поиск и правила «подходит», дальше система сама собирает закупки в реестр, ставит рейтинг с объяснением, при желании просит ИИ оценить соответствие критерию и по кнопке отправляет выбранный тендер в CRM через n8n. Полная спецификация: [docs/spec.md](docs/spec.md).

## Что умеет

- **Профили поиска**: форма или импорт готовой ссылки расширенного поиска с сайта; у каждого профиля свои отсев, правила баллов, критерий для ИИ и интервал автосбора.
- **Сбор выдачи** через httpx без браузера, по одному запросу с паузой 2-4 с; обход останавливается, когда на странице нет новых и обновлённых закупок. Дедупликация по реестровому номеру, история изменений цены, срока и этапа.
- **Карточка закупки** запрашивается только для прошедших отсев: ОКПД2, обеспечение заявки и контракта, место поставки, ИНН заказчика, время окончания подачи.
- **Рейтинг** `(1 - w) * правила + w * ИИ` с разбивкой: какие правила сработали и на какую цитату опёрся ИИ.
- **ИИ-оценка**: YandexGPT (по умолчанию), GigaChat, OpenAI или локальная модель с OpenAI-совместимым API. Ответ модели — строгий JSON `{score, verdict, reasons[], quotes[]}`, проверяется Pydantic; каждая цитата должна дословно (с точностью до пробелов) встречаться в тексте закупки, иначе балл ИИ равен 0. Результаты кешируются по `(номер закупки, хеш критерия, хеш текста)`.
- **Веб-реестр** (FastAPI + Jinja2 + HTMX, только `127.0.0.1`): таблица с фильтрами, сортировкой и поиском, подсветка срока подачи меньше 3 дней, смена статуса без перезагрузки, карточка, профили с редактором правил, настройки, журнал прогонов, выгрузка выборки в Excel.
- **Планировщик** внутри процесса веб-приложения: автосбор по интервалу каждого профиля, ежедневная сводка в Telegram.
- **CRM через n8n**: кнопка «В CRM» отправляет JSON `tender.v1` на вебхук, ответ сохраняется в журнале отправок. Готовые сценарии amoCRM, Bitrix24 и универсальный лежат в [n8n/](n8n/README.md).

## Быстрый старт

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env            # ключи ИИ и порт; значения по умолчанию рабочие
uv run zakupki-monitor init-db

# профиль из ссылки расширенного поиска (или создайте его в веб-интерфейсе)
uv run zakupki-monitor profile import-url "https://zakupki.gov.ru/epz/order/extendedsearch/results.html?searchString=..." --name "Мой поиск"
# профиль с правилами из файла: profiles-example/gas-design.yaml
uv run zakupki-monitor profile add --file profiles-example/gas-design.yaml

uv run zakupki-monitor serve    # http://127.0.0.1:8765
```

В интерфейсе: «Профили» -> «Собрать сейчас» (или задайте интервал автосбора в профиле), результаты в «Реестре», ход прогонов в «Журнале прогонов». Командная строка работает и без веб-интерфейса:

```bash
uv run zakupki-monitor collect --max-pages 2     # --profile "Имя" для одного профиля
uv run zakupki-monitor tenders list --top 20     # по убыванию рейтинга
```

### ИИ

Ключи задаются только в `.env` (см. `.env.example`), провайдер выбирается на странице «Настройки». Без ключей или без критерия в профиле рейтинг считается только по правилам. Провайдер `demo` — заглушка для показа: вердикты собираются из совпадений слов, а в подвале интерфейса стоит пометка «Демо-режим». Реальные API в тестах не вызываются.

### CRM через n8n

1. Импортируйте один из сценариев из `n8n/` и назначьте учётные данные (инструкция в [n8n/README.md](n8n/README.md)).
2. В «Настройках» укажите адрес вебхука n8n и, если нужно, имя заголовка и секрет.
3. В карточке закупки нажмите «В CRM»: запрос и ответ попадут в журнал отправок, статус станет «В CRM».

### Telegram-сводка

В «Настройках» включите сводку, укажите токен бота, `chat_id`, порог рейтинга и час отправки. В сводку входят новые закупки с рейтингом не ниже порога и срочные (до окончания подачи меньше 3 дней). Кнопка «Отправить тестовую сводку сейчас» проверяет связь.

### Демо-данные для скриншотов

```bash
uv run python scripts/demo_seed.py [--shift-deadlines]   # data/demo.db из сохранённых страниц
ZM_DB_PATH=data/demo.db uv run zakupki-monitor serve
```

## Как это работает

- Запросы к ЕИС идут без прокси из окружения, по одному, с паузой 2-4 с, тремя попытками и честным `User-Agent`. Сертификаты Russian Trusted Root CA и Sub CA лежат в `certs/ru-ca.pem` и применяются только к запросам проекта.
- ОКПД2: у 44-ФЗ код позиции берётся из таблицы «Информация об объекте закупки» самой карточки, у 223-ФЗ с вкладки «Список лотов» (один дополнительный запрос на закупку). ИНН заказчика 44-ФЗ извлекается из ИКЗ.
- Прокси из переменных окружения не используются нигде; для ИИ и Telegram при необходимости задайте `ZM_PROXY`.
- Веб-интерфейс слушает только `127.0.0.1`, чужие значения заголовков `Host` и `Origin` отклоняются. HTMX лежит в проекте (`zakupki_monitor/web/static/htmx.min.js`, версия 2.0.4), внешние скрипты не подгружаются.
- Формат файла профиля (YAML или TOML): разделы `search` (или `url`), `max_pages`, `filter`, `rules`, `ai`. Типы правил: `keyword`, `okpd2` (префикс), `customer` (подстрока или ИНН), `price_range` (`от-до`), `days_to_deadline`. Вес правила может быть отрицательным (штраф).

## Проверка качества

```bash
uv run pytest
uv run ruff check . && uv run mypy zakupki_monitor tests scripts
```

Тесты работают без сети на сохранённых страницах из `tests/fixtures/` (общедоступные данные ЕИС), ИИ, n8n и Telegram подменены заглушками.

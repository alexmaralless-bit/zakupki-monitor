# Монитор госзакупок

Демонстрационный проект: собирает закупки с zakupki.gov.ru по сохранённому поиску, раскладывает их в локальную базу SQLite и ставит рейтинг по правилам пользователя. Один пользователь, установка на своём компьютере. Полная спецификация: [docs/spec.md](docs/spec.md).

Сейчас готов **этап 1 («Ядро»)**: профили поиска, сбор выдачи, разбор, дедупликация с журналом изменений, отсев и баллы по правилам, командная строка. Веб-реестр, ИИ-оценка, отправка в CRM и Telegram-сводка относятся к этапу 2.

## Запуск этапа 1

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env            # по желанию, значения по умолчанию рабочие
uv run zakupki-monitor init-db

# профиль из ссылки расширенного поиска с сайта
uv run zakupki-monitor profile import-url "https://zakupki.gov.ru/epz/order/extendedsearch/results.html?searchString=..." --name "Мой поиск"
# или из файла с правилами (пример: profiles-example/gas-design.yaml)
uv run zakupki-monitor profile add --file profiles-example/gas-design.yaml
uv run zakupki-monitor profile list

uv run zakupki-monitor collect --max-pages 2     # --profile "Имя" для одного профиля
uv run zakupki-monitor tenders list --top 20     # по убыванию рейтинга; --filtered покажет отсеянные
```

## Как это работает

- Запросы идут через httpx без прокси из окружения, по одному, с паузой 2-4 с, тремя попытками и честным `User-Agent`. Сертификаты Russian Trusted Root CA и Sub CA лежат в `certs/ru-ca.pem` и применяются только к запросам проекта.
- Обход выдачи идёт по дате обновления и останавливается на странице без новых и обновлённых закупок либо на лимите страниц.
- Карточка закупки запрашивается только для закупок, прошедших отсев.
- Закупки уникальны по реестровому номеру; изменения цены, срока, этапа и даты обновления пишутся в `tender_events`.
- Рейтинг: отсев (с причинами) -> баллы по правилам, нормированные к 0-100, с разбивкой -> слой ИИ (на этапе 1 отсутствует). Итог: `(1 - w) * правила + w * ИИ`; без ИИ равен баллам по правилам.

Формат файла профиля (YAML или TOML): разделы `search` (или `url`), `max_pages`, `filter`, `rules`, `ai`. Типы правил: `keyword`, `okpd2` (префикс), `customer` (подстрока или ИНН), `price_range` (`от-до`), `days_to_deadline`. Вес правила может быть отрицательным (штраф).

## Проверка качества

```bash
uv run pytest
uv run ruff check . && uv run mypy zakupki_monitor tests
```

Тесты работают без сети на сохранённых страницах из `tests/fixtures/` (общедоступные данные ЕИС).
